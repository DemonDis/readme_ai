# Smart Diff Analysis — Update README

## Логика работы команды Update (readme-ai.update)

### Пошаговый алгоритм

**Шаг 1. Валидация**
- Проверить, что открыта рабочая папка
- Прочитать `.ilnsk` — если нет или не заполнен API Key/URL/Model → выход
- Проверить, что `README.md` существует
- Проверить, что папка — git-репозиторий

**Шаг 2. Поиск хэша**
- Прочитать `README.md`
- Найти `<!-- readme-ai: <HASH> -->`
- Если нет → выход (README не от readme-ai)

**Шаг 3. Проверка изменений**
- `git diff <HASH>` и `git diff --name-status <HASH>`
- Собрать все изменённые файлы (кроме README.md)
- Если изменений нет или изменился только README.md → диалог «Force Update?»
- Без Force Update → выход

**Шаг 4. Выбор режима контекста**
- Сравнить `rawDiff.length` с порогом `README_AI_DIFF_MAX_SIZE`
- **Если diff ≤ порога (diff-only):**
  - Отформатировать diff в markdown
  - Склеить: промпт + старый README + отформатированный diff
  - Отправить как единый prompt (без repomix)
- **Если diff > порога (repomix):**
  - Запустить repomix → XML со всеми файлами проекта
  - Вырезать README.md из XML (AI не должен видеть старый README как код)
  - Показать количество токенов

**Шаг 5. Генерация через AI**
- Прочитать `src/prompts/update.md` (короткий русский промпт)
- **В diff-only режиме:** `AiService.generateReadme(url, key, model, '', fullContext)` — всё в одном промпте
- **В repomix режиме:** `AiService.generateReadme(url, key, model, repomixContent, promptContent)` — код отдельно
- AI получает: промпт + контекст + «выведи только README»

**Шаг 6. Запись результата**
- Получить хэш HEAD (`git log -1`)
- Записать ответ AI в README.md
- Добавить `\n\n<!-- readme-ai: НОВЫЙ_ХЭШ -->`
- Открыть файл в редакторе

## Ключевые решения

### Почему выбран гибридный подход (diff-only + repomix)
- **Мелкие изменения (≤5000 символов):** repomix избыточен — тратит время, токены и может запутать AI лишним кодом. Git diff'а достаточно для понимания изменений.
- **Крупные изменения (>5000 символов):** diff слишком фрагментирован, AI нужен полный контекст проекта для точного README.
- Порог настраивается через `README_AI_DIFF_MAX_SIZE` (env).

### Почему в diff-only режиме передаётся старый README
В diff-only режиме AI видит старый README, потому что контекст ограничен — AI легко различает «что было» и «что изменилось». Риск копирования низок при маленьком diff'е. Это сохраняет ручные правки.

### Почему в repomix режиме старый README НЕ передаётся
В repomix режиме контекст большой, AI часто копирует старый README игнорируя инструкции по обновлению. Вырезание README из XML решает проблему галлюцинаций.

### Почему нужен Force Update
Если хэш совпадает с HEAD, diff пустой — изменений нет. Но README мог быть сгенерирован с галлюцинациями, и пользователь хочет перегенерировать. Force Update пропускает проверку diff.

### Почему проверяются только не-README файлы
После Force Update README.md меняется, но не коммитится. При следующем запуске `git diff` показывает изменения README. Без фильтрации это создаёт бесконечный цикл перегенераций.

## Переменные окружения

| Variable | Default | Описание |
|---|---|---|
| `README_AI_DIFF_MAX_SIZE` | `5000` | Макс. длина сырого diff'а (символов). Меньше — diff-only, больше — repomix |
| `README_AI_DIFF_TRUNCATE` | `8000` | Обрезать diff до N символов перед отправкой AI |

## Варианты использования

| Ситуация | Поведение |
|---|---|
| Хэш не найден в README | Ошибка: «README.md not generated by readme-ai» |
| Есть новые коммиты, diff ≤ порога | Diff-only: быстрый апдейт без repomix |
| Есть новые коммиты, diff > порога | Repomix: полный контекст проекта |
| Хэш = HEAD, изменений нет | Диалог: «No code changes detected. Force Update?» |
| Хэш = HEAD, README изменён (Force Update) | Диалог (без фильтрации — бесконечный цикл) |
| Проект пустой (только конфиги) | AI пишет: «проект пустой/минимальный» |
| В проекте есть реальный код | AI генерирует README под код, без выдумок |
